# TEST-08: Accessibility and Lighthouse CI

## Two layers

1. **`tests/e2e/test_a11y.py`** — Playwright-only checks, runs in CI
   with the e2e job (no axe-core dependency):
   `<html lang>`, non-empty `<title>`, `alt` on every image, programmatic
   labels on every form control, accessible names on buttons, exactly one
   `<h1>`, body text/background contrast ≥ 4.5 (WCAG AA).
2. **`.github/workflows/lighthouse.yml`** — Lighthouse CI against
   `/`, `/login`, `/resume` with budgets (perf ≥ 85, a11y ≥ 95,
   best-practices ≥ 95, SEO ≥ 90). Config:
   `.github/workflows/lighthouserc.json`.

## Known gaps (pinned, fail on anything new)

`test_a11y.py::KNOWN_GAPS` pins the current baseline so the suite stays
green while catching regressions. **Currently empty:** both pinned gaps
were fixed in the 2026-10-25 a11y sweep (commit 4b8ea3d) and their
entries deleted per the contract below — `/resume` `#fileInput` gained
`aria-label="Upload your resume"`, and the dashboard goal `title` input
gained a programmatic label.

`test_known_gaps_still_documented` fails if a pinned gap disappears
without being removed from the list (prevents stale allow-lists).
Fixing a gap = fix the template + delete the entry.

## Baselines (measured 2026-10-19, local Chromium headless)

- Body contrast ratios: `/` 19.3, `/login` 19.3, `/register` 19.3,
  `/resume` 15.7 — far above the 4.5 floor.
- lang=`en`, single `<h1>`, all images have `alt` — clean on all pages.
- **Lighthouse: no measured baseline yet.** The budgets above are the
  roadmap's targets (TEST-08). The first green `lighthouse.yml` run
  establishes the real baseline; if a budget fails there, tune the
  budget to the measured value here rather than silently weakening it.
