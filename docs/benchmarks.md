# Benchmarks (ENG-09)

Gold-standard datasets and reproducible evaluation harness for STUDY-BUDDY's
parsing and extraction engines.

## Datasets

| Dataset | Location | Size | Description |
|---------|----------|------|-------------|
| Resume gold | `benchmarks/resume_gold/` | **120 synthetic** | Name, email, phone, skills labeled |
| Resume ATS cases | `benchmarks/resume_cases.json` | 120 (same set) | Expected ATS band per resume |
| JD gold | `benchmarks/jd_gold.json` | **30 JDs** (10 roles × 3 levels) | Must-have skills + matched/mismatched resume links |
| RAG gold | `benchmarks/rag_eval.py` (inline corpus) | **56 questions** over 8 docs | 48 answerable + 8 unanswerable |

Synthetic resumes cover: Indian formats (+91 phones), fresher / 1–3 yrs /
5+ yrs, 10 roles, quality levels strong / average / weak / thin / gaming
(keyword-stuffed). Generated by `benchmarks/generate_gold.py` (seeded,
reproducible). Two deliberate hard parser cases are kept and documented:
one international phone (+34, not matched by the +91 regex) and one
ALL-CAPS name with a double space (not matched by the name regex).
JD gold is generated by `benchmarks/generate_jd.py` (seeded); every
must-have skill is a canonical name from `data/skills_db.csv`.

## Running

```bash
# Resume extraction — quick (10 items) / full (120)
python benchmarks/run.py --quick
python benchmarks/run.py

# ATS scoring over the 120 gold resumes (band checks + anti-gaming)
python scripts/benchmark_resume.py --cases benchmarks/resume_cases.json

# JD match — quick (10 JDs) / full (30)
python benchmarks/run_jd.py --quick
python benchmarks/run_jd.py

# RAG — quick (4 questions) / full (56)
python benchmarks/rag_eval.py --quick
python benchmarks/rag_eval.py
```

Results are written to `benchmarks/results.json` (resume extraction),
`benchmarks/jd_results.json` (JD match) and `benchmarks/rag_results.json`
(RAG). ATS results print to stdout (no file written).

### JD match (`benchmarks/run_jd.py`, n=30 JDs, 165 must-have skills)

| Metric | Score |
|--------|-------|
| Must-have skill recall (extractor on JD text) | 1.00 (min 1.00) |
| Matched-resume score (mean) | 52.7 |
| Mismatched-resume score (mean) | 33.2 |
| Separation (matched − mismatched, mean) | 19.5 |
| Ranking accuracy (matched > mismatched) | 1.00 (30/30) |

Notes: the matched absolute score is modest because keyword coverage
(11.8/40) counts all top-60 JD keywords, including boilerplate no resume
contains — that is a property of the production scorer, not the harness.
Separation is weakest on generalist roles (fullstack 10.2, ml-engineer
12.9, fresher 13.5) and strongest on specialised ones (data-engineer
24.6, frontend 23.8, devops 23.2). Experience alignment does not
discriminate roles (mismatched 14.2 vs matched 12.2) — it is
role-agnostic by design; the separation comes from keywords (11.8 vs
4.9) and skills (18.7 vs 4.1).

### RAG (`benchmarks/rag_eval.py`, n=56 questions over 8 docs)

| Metric | Score |
|--------|-------|
| Recall@1 / @3 / @5 | 1.00 / 1.00 / 1.00 |
| MRR | 1.00 |
| Answer accuracy (expected fact in answer) | 1.00 (48/48) |
| Abstention accuracy | 0.625 (5/8) |
| Citation validity | 1.00 |

Notes: retrieval is perfect on this synthetic corpus because the 8 docs
have deliberately distinct vocabularies — treat recall@1 = 1.00 as a
ceiling on clean data, not a production claim. Abstention is 5/8 by
design: 5 clean unanswerable questions (zero token overlap) abstain, but
3 near-miss questions fail — each shares one token with the corpus
("mars", "year", "how"). Root cause: `retrieve()` normalises scores, so
a single shared token gives the top chunk a combined score of 1.0, which
clears the 0.05 relevance threshold and produces a (wrong) answer. That
is a real retriever limitation, not a benchmark artifact. Also: the
sentence splitter cuts decimal numbers ("1.5" → "1."), so the Paris
Agreement fact is spelled out ("one and a half degrees") in the corpus.

*Note: scores are on synthetic data with clean formatting. Real-world
resumes (double-column, scanned PDFs, varied layouts) will score lower.
Expand the gold set with challenging cases before claiming production accuracy.*

### What we do NOT claim

- No "ATS score" and no "beats the ATS" claims anywhere (ENG-01): the
  readiness score is a labelled transparent heuristic with
  `heuristic: true` in API responses.
- Synthetic benchmark numbers stay labelled synthetic until measured on
  consented, anonymized real-world samples — the label changes when that
  happens, not before.
